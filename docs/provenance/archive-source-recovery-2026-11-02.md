# Historical archive source recovery — 2026-11-02

## Scope and rule

The pinned IMUD main tree contains partial archive directories. Their names encode historical commit IDs or version labels, and the repository still exposes branches V20.1–V20.5. This audit checks the exact source trees corresponding to those labels.

This is a **provenance and recovery audit**, not a merge and not an automatic resolution of the primary manifest. V21/Gold and V23/Orange/Green remain independent. A file found in another historical commit is only a candidate source until the commit is represented as a separate source profile or an exact content mapping is explicitly accepted.

The exact refs and tree SHAs are in `historical-archive-source-pins.json`.

Extractor corrections in e2e2831:

### V19 and V21 font paths

Both historical `app.js` files build a font URL using `fetch('fonts/' + fontFile)`. The scanner had previously treated the array basenames as root paths. The corrected manifest now records `fonts/<filename>`. All 13 such files exist under `fonts/` in the exact V19 and Gold V21 commits. This is a path-normalization correction, not a change to source files.

### V20.1

Six unresolved code/asset paths (app.js, check_layout.js, decorations.js, settings-manager.js, style.css, typesetter.js) exist at the exact V20.1 branch commit. `fuzz_last.json` is generated by `fs.writeFileSync` and is no longer classified as an input. `doc_full.txt` and `doc_part1.txt` are read by `fuzz.js` but are absent from the exact V20.1 branch tree.

### V20.2, V20.4 and V20.5

All referenced missing data paths exist at the corresponding exact branch commits. The V20.2 archive has two same-path file differences against its branch head (`script.js` and `styles.css`); retain those differences until a content-level owner decision.

### V20.3 work_v4

## Decision and next steps

1. Keep the primary six-profile manifest unchanged in scope; do not silently resolve one profile's dependencies from another profile.
2. Preserve the seven exact historical refs as read-only pins.
3. Decide whether to add the V19/V20.1–V20.5/V21 historical trees as explicit, separate manifest profiles. If added, retain their own compatIds and profile identities.
4. Obtain or explicitly waive the 17 targets not found in the checked corresponding commits; do not create placeholders.
5. Keep Stage A open. This work advances source-of-truth mapping and extractor accuracy; it does not close the remaining Stage A gates or authorize Stage B.
